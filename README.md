### See the storm before it reaches the grid.

Transparent, weighted storm-risk scoring for Ontario distribution operators — wind, canopy, flood exposure, and outage history fused into a single tier, with an LLM-generated response brief.

</div>

> **The mark.** An arc above the line is the storm front sweeping in. Three short strokes beneath it are people, poles, and feeders we watch. The amber tick in the centre is the place being assessed right now. The brand is mono everywhere; the amber is reserved for the one signal that matters.

---

## Overview

GridGuard takes any Ontario location, geocodes it, fetches live weather from Environment Canada, looks up local static layers (tree canopy density, flood footprints, recent storm-related 311 history as an outage proxy), and produces:

- a normalized **risk score (0–100)** with an explicit **Low / Medium / High** tier,
- a **per-factor breakdown** showing raw value, normalized score, weight, and contribution,
- a **plain-language operator brief** generated by Gemini (or a deterministic local fallback when no key is set),
- an **interactive map** with the assessed zone and an **Ontario explore view** of key cities.

Everything that goes into the score is shown back to the operator. No black-box numbers.

## Stack

- **Next.js 15** (App Router) — frontend + API routes in one process
- **TypeScript** end-to-end
- **Tailwind v4** + custom design tokens (Emil-Kowalski-flavored easing, stagger, scale-on-press)
- **Leaflet** + Carto dark basemap for the explore map and result map
- **Nominatim (OSM)** for geocoding
- **Environment Canada MSC GeoMet** for live weather
- **Google Gemini** for the operator narrative (optional, transparent fallback)

## Scoring model

```
risk_score = 100 × clamp01(
    0.30 × wind
  + 0.25 × canopy
  + 0.25 × flood
  + 0.20 × outage_history
)
```

Tiers: `< 35 Low`, `35–65 Medium`, `> 65 High`. Weights, normalization, and inputs are all surfaced in the UI.

## Data

Raw datasets live under `datasets/` (gitignored) and are preprocessed into small derived JSON indices under `datasets/derived/` via:

```bash
npm run build:data
```

Sources are documented in [`datasets/README.md`](datasets/README.md).

## Getting started

```bash
npm install
npm run build:data    # one-time, ~10–20s, builds derived indices
cp .env.example .env  # optional, add GEMINI_API_KEY for live narratives
npm run dev
```

Then open <http://localhost:3000>.

## Project layout

```
app/
  api/assess/route.ts   Orchestrates geocode → weather → score → narrative
  page.tsx              Landing page, search, map explore, results
components/             RiskGauge, FactorBreakdown, MapPanel, MapExplore, …
lib/
  geocode.ts            Nominatim + fetchWithTimeout
  weather.ts            MSC GeoMet parsing
  datasets.ts           Derived-index lookups (FSA, canopy grid, flood polys)
  scoring.ts            Weighted formula + tier mapping
  llm.ts                Gemini call + local fallback
  fetchWithTimeout.ts   Reliability wrapper
scripts/
  build-indices.mjs     Streaming preprocessor (regex GeoJSON for speed)
```
